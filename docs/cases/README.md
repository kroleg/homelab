# Investigation cases

Keep durable records of non-trivial troubleshooting and research here. Use one descriptive Markdown file per case; update it as evidence arrives.

Each case should capture:

- Goal and current status.
- Relevant environment and devices, without credentials.
- What was tested, the observed result, and the source/date of evidence.
- What failed or caused regressions, including approaches not to repeat.
- Proposed options, clearly separated from tested solutions.
- Open questions and the next useful checks.
- Relevant local files and external references.

Distinguish direct observations, user reports, historical records, and hypotheses. Do not present a proposal as a working solution or infer that a requested change was executed. Keep the current conclusion prominent and retain meaningful failed attempts.
